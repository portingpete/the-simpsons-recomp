# Audio catalog source extent audit (2026-10-03)

The native catalog loader now accepts source metadata above 512 MiB. The unchanged catalog generator accepted an actual isolated 536,891,968-byte SNU, but the old loader rejected its Source64 row. The repair removes only that per-source metadata ceiling. Catalog buffer, table, path, framing, ordering and subtraction-based extent checks remain in place.

The generator records the actual source length and full-file SHA256 in Source64. Its source length is an unsigned 64-bit field; stream, block and layer file offsets are also wide. The loader describes those sources without allocating their declared lengths. The separate 512 MiB limit on the catalog buffer bounds an actual allocation and was retained. See the [source range review](../build/restrictive-audit/catalog-source-extent-range-20261003/range-review-v1.json).

The regression authenticates `audiostreams/cb_xxx_0/d_chcb_xxx_0006700.exa.snu`, SHA256 `1034445fb02bdb156570b4d4ae82157ee99816986ae98f8fa56b685ad2172bba`. It copies the original wrapper and unchanged audio into a private sparse fixture, changes only the copied audio-offset word, inserts a zero gap, and runs the unchanged generator. The shipped source stays untouched.

Each repaired execution opens and hashes the actual sources, seeks to every block, matches the generated certificate, parses the original packets, and prepares, stages, commits and retires every decoder receipt. Both relocated use and reopening produce the same complete PCM as the original: SHA256 `1924b6830424185a1ef1d4ef233791cf2dc590dcd6efc2de5798e72a53e2154c`. Caller packet vectors are poisoned and destroyed before staging. Every retired receipt rejects query and stage with the exact stale diagnostic. Explicit close releases codec and source storage; an otherwise valid new segment then rejects at the exact closed-owner guard without changing the closed snapshot. The file closes and local owners destruct before the case returns.

The five malformed cases independently reject zero source extent, a source shorter than its audio, a wrapping audio offset, a header outside the source and an invalid source kind. They use the small original catalog so the old size ceiling cannot mask their intended guards. Exact caught diagnostics are assertions in the hash-pinned test source; raw rows record each passed control and its full input tuple. Each run retains 22 raw rows covering the eight cases and three completed lifetimes.

The selected tests also cover the complete shipped catalog admission, existing native XMA ownership, Python catalog generation and streamed loop catalog checks. Each compiled scope hashes 1,220 source/header inputs, four selected executable identities, three DLLs and 642 configured object dependency records. Actual builds complete 11 Native and 12 Release steps, including the changed catalog compilation and application link. AOT verifies 311 files with zero semantic diagnostics. The project now registers 501 CTests; no full 501-test aggregate was run for this change. Earlier full 500 and profile-only 18-test runs retain their original source scopes.

Original console large-file setup, guest reader scheduling, device playback, sample seeking and mission gameplay remain unqualified. Original MUS setup uses word arithmetic; filesystem seek limits depend on the caller and high-word lane. Those details are retained in the [filesystem supplement](../build/restrictive-audit/catalog-source-extent-range-20261003/original-filesystem-wrapper-supplement-v1.json), without claiming a universal 2 GiB cap.
