# Native effective screen state

`renderer/engine_state.h/.cpp` owns a bounded CPU representation of the original SDK's effective screen state. `tests/test_engine_state.cpp` verifies the original bytes and behavior independently of the runtime. There are no guest memory writes, pending/applied caches, SDK objects, target bindings, GPU commands, CMake changes or renderer changes in this implementation.

Evidence is the US flat image `analysis/simpsons.pe`, base `82000000`, size 15,466,496, SHA256 `6df9123532f4f7f8f00ac30642849058725562f43339461561522c5d442083a0`; the original scalar table `82CD28B8`, sampler table `82CD2D78`, SDK initialization `82466800`, engine initialization `824008E0`, and screen helper `82756480`. The detailed source ledger is [native-driver-state.md](native-driver-state.md); shader/quad evidence is [screen-material.md](screen-material.md). Read-only reference field names came from `K:/Simpsons/RexGlueCurrent/include/rex/graphics/{registers,xenos}.h`. No reference backend was copied.

## Bridge API and transaction boundary

A default-constructed `EngineState` is deliberately unusable. `EngineState::fromOriginalStartup()` constructs the proven SDK-default-plus-engine-override baseline, with sixteen application sampler stages and four independent effective blend words. The first eight stages receive RenderWare overrides; stages 8..15 retain SDK defaults. It does not claim the original initializer ran or initialize any guest state. `scalarStateEvidence()` now exposes 82 supported scalar fields; the additional blend-constant, coverage and stencil fields are documented in [native-application-state.md](native-application-state.md), including original-AOT differential validation. `samplerStateEvidence()` preserves all 20 original sampler defaults; all twenty now accept bounded updates. The original application CPU dispatcher is now connected through [native-application-sampler-bridge.md](native-application-sampler-bridge.md).

`setScalar(originalId,value)` and `setSampler(stage,originalId,value)` accept the original **hexadecimal offset IDs**, not desktop D3D enumerations. Typed overloads are provided. Unknown IDs, noncanonical Boolean values, out-of-range fields/stages and unimplemented values throw `EngineStateError` before any mutation. The caller must propagate failure and leave its pending/applied transaction coherent; it must not swallow rejection and submit a draw as if the requested change succeeded. A value-copy of the owner can be used to stage a multi-call transaction. Access is caller-serialized.

This owner represents calls that actually execute at the SDK boundary. It deliberately does **not** suppress equal-value calls: some original setters rebuild effective state even when their requested value is unchanged. The parent bridge owns original `823FFE78`, `82400170`, `824001E0`, `82400040`, `82400278` cache/queue behavior and the mixed initializer's CPU writes. Scalar IDs at or above `194` belong to a different engine CPU pipeline contract and reject here, as do unsupported lower IDs. Sampler evidence/default presence is not evidence that every setter is implemented.

`applyScreenQuadState(selector,textured)` and `finishScreenQuadState(selector)` expose only the proven scalar/sampler effects of `82756480`. They neither draw nor bind a shader, texture, target or vertex declaration. Selectors outside 0..3 reject atomically. The cleanup is a sequence of new state writes, not restoration of an earlier snapshot.

## Baseline and accepted changes

All IDs below are hexadecimal. Startup keeps depth request `28=1`, depth writes `30=1`, comparison `2C=6` GREATER_EQUAL; cull `38=2`; filled mode `34=0`; stencil request `6C=0`; all four color masks `D4/D8/DC/E0=F`; zero bias `CC/D0`; and expanded blend requests `134/138/13C/140=0`. Stencil operations remain KEEP, comparison ALWAYS, reference zero and raw masks FFFFFFFF (effective low byte FF). Those inactive stencil fields, fill and bias accept only their documented baseline values in this bounded implementation.

Canonical enable fields accept 0/1. Depth/alpha comparisons and cull preserve their three-bit raw fields; color masks preserve four bits. The gate is stricter than this storage API. Alpha reference `64` accepts only integers 0..255, deliberately rejecting the SDK's broader unsigned input range. Original `8243A438` converts that integer to float32 and multiplies by float32 bits `3B808081` at `821DD204`. Thus quad argument **1 means float32(1/255), not bit-cast float bits 00000001**. All 256 accepted references are tested. Enabled alpha comparison `68` must be GREATER=4 for the screen gate; an inactive comparison remains retained.

Depth `8243A6C8` stores the requested value at device `+2E5C`, while effective depth test also depends on a nonzero depth surface at `+30A0`. Stencil `8243A770` similarly retains its request at `+2E60`. `effectiveDepthTest(depthSurfaceBound)` and `effectiveStencilTest(depthSurfaceBound)` make that dependence explicit without owning a surface. The screen gate requires both requests zero regardless of binding, so it cannot accidentally infer a missing depth surface. Retained depth writes and comparison are preserved while testing is off; raw write-enable need not be zero for a depth-disabled screen pass.

Sampler stages 0..7 start with min/mag request 1 LINEAR (`14/10`), U/V/W repeat 0 (`0/4/8`), mip policy 2 BASE_MAP (`18`), zero bias bits (`1C`), minimum mip zero (`20`), anisotropy one (`24`) and raw maximum mip 13 (`34`). The linear branch is selected by original capability word `8206AA70=07030700`; the inline base-map write at `82400BA4` is accounted for. Border selector `C=0` remains inactive under repeat addressing; its color/alpha is not invented.

Sampler updates support raw address fields 0..7, min/mag 0 or 1 and mip policy 0..2; unsupported choices remain stored but fail the textured screen gate. Other named sampler fields accept only the stated baseline. The three named Z filter flags accept canonical Booleans; effective volume filtering is computed from normal or separate filters exactly as the original setters. The six remaining auxiliary fields only accept their original SDK baseline. Separate volume filtering rejects at the screen gate. In particular, the anisotropy/override bytes read by `8243BA40/8243BBD0` cannot silently change underneath a claimed linear sampler. Nonzero LOD bias, alternate minimum/maximum mip, anisotropy changes and border changes require new proof before support. A flat shader does not consume sampler state.

## Requested blending is not effective blending

The original scalar blend shadows are device `+2E40` (requested factors/operations) and `+2E44` (enable/separate-alpha). Their fields are RGB source bits 0..4, RGB operation 5..7, RGB destination 8..12, alpha source 16..20, alpha operation 21..23, alpha destination 24..28. Accepted factors fit five bits and operations fit three; storing an unnamed factor is not authorization to render it. `requestedBlendWord()` returns this separate shadow.

Startup requested RGB factors are source-alpha=6/destination-inverse-source-alpha=7, operation ADD=0, separate alpha disabled. Effective words are still replacement `00010001`, because scalar blend enable `3C=0`. Disabling never erases the requested factors.

`3C -> 8243A010` and `40 -> 8243A3A0` always rebuild all four effective words when called, including equal-value calls. RGB field setters `48/4C/50` publish only with enable set; alpha field setters `54/58/5C` publish only with enable and separate-alpha both set. A rebuild uses replacement if disabled, the requested word if separate alpha is enabled, or the exact nonseparate transform at `8243A028..A044`. For each RGB factor `f`, the derived alpha factor is `(f & F) | (f >> 4)`; merely copying the RGB halfword is wrong for high factor bits. Tests cover all 8,192 source/destination/operation combinations.

`setPackedBlend(target,word)` models `8243CB80`: copy the supplied uint32 verbatim to just one effective target word, without changing or consulting those scalar shadows. Unknown words are retained but fail the target-0 screen gate. Targets are bounded to 0..3. The four recognized effective words are `00010106`, `00010706`, `00010186`, `00010001`, corresponding to the original quad selectors 0..3. They select source-alpha/add/one, source-alpha/add/inverse-source-alpha, source-alpha/reverse-subtract/one, and one/add/zero for RGB; all use alpha one/add/zero. A packed quad word remains effective even while the scalar enable is zero.

## Quad effects and snapshot limits

Quad setup writes depth request off, cull off, alpha test on/GREATER/reference integer 1, and its selected packed target-0 word. Selectors 0..2 additionally request expanded blending through `8243B3B0`; selector 3 leaves any inherited expanded request untouched. Only the textured branch sets stage-0 linear min/mag and U/V repeat; W, mip, other stages, stencil and masks are inherited. Cleanup disables scalar blending (broadcasting replacement to **all four** targets), disables alpha test and enables the depth request; selectors 0..2 also clear expanded blending. Cull, alpha comparison/reference, sampler changes and requested factors are not restored.

`requireScreenState(textured)` returns an independent value snapshot or throws. It proves, for this subset: depth/stencil requests off; cull off; filled polygons; target-0 color mask F; zero bias; one of the four proven **effective** blend equations; expanded request off; and supported enabled alpha-test behavior. The textured variant additionally requires stage-0 linear/repeat/base-map-only, zero bias, minimum mip zero, anisotropy one and the retained startup maximum mip. A native base-level sampler for the proven one-level resources selects level zero; do not reinterpret raw maximum mip 13 as trilinear sampling or silently rewrite it to zero in this owner.

**Expanded blending is intentionally blocked.** Original `8243B3B0` can change target format 2→10 or 3→12 to alter blending precision. This owner has no target-format or native precision proof and conservatively rejects any active target-0 request, even when a different target format might make it inactive. Therefore the original selector-0 loading spinner, and selectors 1/2 after their full quad setup, are still unsupported. Do not clear that request merely to pass the gate. Directly representable blend arithmetic does not close the precision question.

A successful snapshot is **not a draw permit or an original-frame claim**. The bridge must separately verify the current original target/viewport, single-target binding, format/sign/gamma/alpha interpretation, one-level 2D texture resource/view, shaders/declaration, and any rasterizer/sample/scissor/other state outside this subset. This service neither assumes defaults for unnamed scalar state nor certifies a whole pipeline. All relevant mutations must reach the owner or be rejected at their service boundary; bypassing it invalidates its evidence. Snapshot freshness/transaction ordering also belongs to the bridge.

## Original baseline validation and subsequent integration

Standalone ClangCL C++20 `/W4 /WX /O2` compilation succeeded, followed by **9 groups / 9,351 checks** against the original flat image. Tests check the 34 scalar/20 sampler table rows and selected original instruction/constants, reject a changed table fixture, check initialization requirements and all eight samplers, depth/stencil binding dependence, packed-versus-requested blend lifetime and equal-value publication, exhaustive blend factor conversion, inherited-state gates, exact quad cleanup, rejection rollback, bounded IDs/stages/values, all alpha byte inputs, and independent snapshots/owner copies. A separate read-only review found no correctness issues. The byte checks pin the consumed evidence, not every byte of the executable; full original-image hash verification remains the parent runtime's responsibility.

Build only `renderer/engine_state.cpp` and `tests/test_engine_state.cpp` together with C++20 and the workspace include path; run the executable with `analysis/simpsons.pe` as its sole argument. No D3D library is required. Test binaries/objects were temporary and removed. The parent owns CMake integration, guest CPU cache/state initialization, runtime hooks, native resource bindings and rendering. These four new files are ready to freeze at this bounded state contract.

Build079 integrates 82 scalar fields, all twenty sampler categories and sixteen application stages: 9,822 effective-state checks, 8,019 actual original state-bridge checks and 1,207 driver checks. All 23 CTest suites pass. The screen gate additionally rejects the application half-pixel and guardband policy pending native raster proof. See STATUS.md for the current executable boundary.
