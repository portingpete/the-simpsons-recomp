# ResourceAudit stable grouping review

The original source-only review of the frozen 500-test submesh repair snapshot is preserved in `build/restrictive-check-audit/resource-audit-stable-group-review-source500-20261002.json`. Its proposed diffs remain historical inputs under `build/restrictive-audit/resource-audit-grouping-review-source500-20261002/`. A subsequent authorized snapshot applied the two bounded producer changes below after independent test-first failures. The review did not receive execution credit retroactively; the new baseline and repair receipts have separate source/executable identities.

`ResourceAudit::capture` currently groups the exact tuple `[kind, asset, caller, parameters, ownership, mission, last_action]`. It excludes `instance`, thread, sequence, scene and inherited scene context. A duplicate still refreshes the latest failure context. Lifecycle rows always emit, including repeated identical groups. This is the correct generic contract; normalization should occur at a producer whose original argument roles are known.

## Reviewed fields that remain keys

All production ResourceAudit callsites under `runtime` and `renderer` are inventoried in the JSON, including duplicate/fallback sites. Graphics owner/cache/packet/geometry addresses, allocator extent generations, native IDs, stack/function/raw arguments and scene counters already enter `instance` or a separately excluded scene field. Shader/source/pass/technique addresses are immutable original identities. Geometry strides, submesh/bone/index counts, selected starts/base vertices and scalar render flags describe the consumed variant and remain keys.

The radial `count` is a vertex reservation extent, `2 * (segments + 1)`, subsequently checked against the original reservation and completion arguments. It is not a cumulative draw counter. The mono `flag` is the original qualified alpha selection, checked against the public immediate or recorded activation; it is not a packet pointer. The producer-entry `flags_low8` is derived from the actual global flags; raw `r31_low8` is already in `instance`. Those fields must remain source-qualified as they are.

Map request/ready/retirement and failure-request producers place owner addresses, boundary ordinals and generations in `instance`. Checkpoint GUIDs, map/episode/mode identities, request flags and cached ownership predicates retain their meaning in the key. Frontend notification is a control value written by original `8239AF68` and tested against dispatch codes such as `1000/1001/1005/1006`, not a notification pointer or monotonically increasing counter. Movie filename/state/flags, frontend selector/index and callback/decoder presence remain semantic keys; actual addresses are instance data.

Audio reader creation keeps the true ring/count/entry/override-presence and qualified stream bitrate/duration inputs. Reader release keys contain finite phase and claim/release predicates; manager/group generation, epoch, operation count and raw lanes are already instance data. Audio source keys contain fresh/control scalar inputs and cached immutable catalog identities, with member/group/state/bank/AMX generations confined to `instance`. Neither audio producer writes last action. Storage selector keys keep the actual requested root, user/type/flags/bytes and finite readiness predicates; output/event/callback/profile identifiers are instance data. No automatic stripping of a real storage path is proposed.

Raw analog values can naturally create many action variants. This review does not reduce that cardinality: caller, mission and last-action semantics were explicitly retained. Unknown or malformed inputs retain their raw instance and explicit unknown/mismatch classifications rather than receiving fabricated catalog identities.

## Ownership attribution gap, separate from grouping

At audio reader boundary `8233D980`, the prevalidation snapshot currently searches for a group with raw `r4`. The functional original close handling reads the actual group from checked `r3+4`. Therefore a valid close may be logged as `registeredGroup=false` before the functional observer resolves it. At `8233D5E8`, `r4=G` has a different source-qualified role. This is missing early close ownership attribution, not a transient key leak. A future diagnostic fix should independently read bounded `r3+4` with unknown-on-unreadable handling, or use a cached exact handle-to-group association. It must preserve raw `r3/r4`, avoid substituting an arbitrary `r4`, and leave validation unchanged.
